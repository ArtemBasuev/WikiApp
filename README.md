# WikiApp

Мультиплатформенное приложение (Kotlin Multiplatform + Compose Multiplatform) для чтения статей Википедии: список статей с поиском, экран статьи, избранное, светлая и тёмная тема, русская и английская локализация.

Данные берутся из живого источника: [MediaWiki Action API](https://www.mediawiki.org/wiki/API:Action_API) английской Википедии (`en.wikipedia.org/w/api.php`). Моки удалены.

## Предметная область

Основная сущность — **статья Википедии** (`WikiPage`):

| Поле | Описание |
|---|---|
| `pageid` | Уникальный идентификатор статьи |
| `title` | Заголовок |
| `extract` | Краткое содержание (вводный абзац) |
| `fullurl` | Ссылка на оригинал |
| `length` | Размер статьи в байтах |
| `touched` | Дата и время последнего изменения (ISO 8601) |
| `categories` | Категории статьи (`Category`) |
| `links` | Ссылки на другие статьи (`PageLink`) |

Сценарии пользователя:

1. **Список.** Без запроса показываются все статьи Википедии в порядке сортировки заголовков, с бесконечной подгрузкой по мере прокрутки. При вводе запроса выполняется поиск на сервере; запрос уходит с задержкой 400 мс, а ввод новой буквы отменяет предыдущий.
2. **Статья.** По нажатию открывается экран с заголовком, метаданными, категориями, текстом и ссылками на связанные статьи. Нажатие на ссылку открывает связанную статью; если статью найти не удалось, показывается сообщение.
3. **Избранное.** Статью можно добавить в избранное и просмотреть список избранного отдельным экраном.
4. **Тема.** Тема переключается с экрана списка (по умолчанию берётся системная).
5. **Ошибки.** Для списка, статьи и избранного есть состояния загрузки и ошибки с кнопкой «Повторить». Если не загрузилась следующая страница списка, ошибка показывается внизу списка, а автоподгрузка останавливается до нажатия «Повторить».

## Источник данных

Все запросы идут на один адрес `api.php` с параметрами `action=query&format=json&formatversion=2`.

| Задача | Запрос |
|---|---|
| Лента статей | `generator=allpages` (без перенаправлений), продолжение по курсору `gapcontinue` |
| Поиск | `generator=search`, продолжение по `gsroffset` |
| Страница по `pageid` | `pageids=…`, свойства `extracts`, `info`, `categories`, `links` |
| Страница по заголовку (переход по ссылке) | `titles=…&redirects=1` |
| Избранное | `pageids=…` пачками до 20 |

Для всех запросов используется `origin=*` (CORS в браузере) и заголовки `User-Agent` / `Api-User-Agent` (политика Wikimedia; в браузере `User-Agent` выставить нельзя).

Адрес API и `User-Agent` в код не зашиты. Они лежат в `gradle.properties` в корне проекта.

## Структура

```
data/
  WikiPage.kt, WikiRepository.kt          модель и интерфейс репозитория
  WikiRepositoryImpl.kt                    репозиторий поверх сети, кэш в памяти
  remote/
    WikiHttpClient.kt                      Ktor HttpClient (без явного движка)
    WikiApi.kt                             запросы к api.php
    WikiPageMapper.kt                      DTO → WikiPage
    dto/WikiDtos.kt                        модели ответа (@Serializable)
core/SuspendRunCatching.kt                 runCatching, не глотающий отмену
list/ detail/ favorites/                   экраны: State / Intent / Effect / ViewModel / Screen
ui/                                        общие компоненты (AppScaffold, CategoryChip, LoadingBox, ErrorBox)
```

- **Модель ответа отдельно от модели экрана.** Разбор идёт в DTO (`WikiPageDto` и др.) с `ignoreUnknownKeys = true`, затем маппится в `WikiPage`. Неизвестные поля в ответе игнорируются.
- **Экран рисуется из состояния.** Вниз уходят `State` и колбэк `onIntent`, а не ViewModel целиком. Состояние отдаётся наружу через `StateFlow`.
- **Репозиторий возвращает `Result`.** Ошибки сети и сервера (в том числе тело `{"error": …}` с кодом 200) превращаются в `Result.failure` и отображаются в состоянии экрана.

## Асинхронность и ошибки

- Вся асинхронность на корутинах. Запрос и разбор JSON выполняются на `Dispatchers.Default`, а не на UI-диспетчере.
- `suspendRunCatching` пробрасывает `CancellationException`: отмена (новая буква в поиске, уход с экрана) не превращается в ошибку на экране.
- Поиск: каждая новая буква отменяет предыдущую корутину (задержку и запрос).
- Подгрузка: порции склеиваются через `distinctBy { pageid }`, ключи в `LazyColumn` остаются уникальными.

## Кэш

В памяти репозитория хранятся загруженные страницы (карточки из списка и полные страницы со ссылками). Он нужен, чтобы не перекачивать избранное и повторно открытые статьи. На диск ничего не сохраняется, при перезапуске приложения кэш и избранное пропадают. Офлайн-режима нет: после первой загрузки часть статей может открыться без сети только потому, что лежит в кэше.

## Запуск

Требуется JDK, совместимый с версией Gradle проекта (рекомендуется JDK 17 или новее). Gradle Wrapper скачает остальное автоматически. Для запуска нужен доступ в интернет.

Десктопное приложение:

```bash
./gradlew :desktopApp:run
```

На Linux и macOS, если `gradlew` не запускается из-за прав доступа:

```bash
chmod +x gradlew
```

Веб-версия:

```bash
./gradlew :webApp:wasmJsBrowserDevelopmentRun
```

Если Gradle сообщает `Lock file was changed` для `kotlinWasmStoreYarnLock`, выполните `./gradlew kotlinWasmUpgradeYarnLock` и закоммитьте обновлённый `kotlin-js-store/wasm/yarn.lock`.

Android-версия:

```bash
./gradlew :androidApp:assembleDebug
```

Проверка локализации:

```bash
python tools/check-strings.py
```
